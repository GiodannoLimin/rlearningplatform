# Synthetic data and provenance

Every observation in Statistics with R is synthetic teaching material. No personal, institutional, or observational dataset is used. The core notebooks use short illustrative vectors and reproducible random-generation definitions in `src/content/`. The practical track also bundles `public/data/orders.csv`, generated by `scripts/generate-practical-data.py`; its complete column dictionary, construction, missing values, intentional defects, and CC0 license are in [the dataset notes](../public/data/README.md). R generates the observations when a learner runs a chunk; tables and plots show actual calculations on those values.

The original example definitions, prose, and application code are covered by the repository's [MIT license](../LICENSE), copyright 2026 Statistics with R contributors. R, WebR, and other dependencies retain their own licenses. Running the examples in native R or in WebR does not change their synthetic provenance; native R verification output is a test result, not an independently collected dataset.

## Finite roster in Notebook 3

The `roster` vector is generated once with `set.seed(3107)` and `rexp(20000, rate = 0.1)`, then held fixed for the recruitment experiments. It contains 20,000 synthetic waiting times in minutes. Vector position is only a record index; no real person, site, timestamp, or external identifier is represented.

`target_mean` is the exact mean of that fixed vector. `eligible` selects entries with waiting time greater than 10 minutes; `selected_mean` is the mean of this subset. Each simulated recruitment study samples with replacement from `eligible`. Comparison studies sample uniformly with replacement from the full `roster`. Repeated values are allowed by design; they are not missing data or accidental duplicate records.

The selection summary table has columns `group` (descriptive label), `entries` (number of eligible records), and `mean_minutes`. The repeated-study table has `n` (draws per study), `target_mean`, `estimated_center`, `simulated_se`, and `bias_from_selection`; its numerical summaries other than `n` are in minutes. The roster is regenerated from its definition instead of supplied as a separate CSV.

## Missing-value and output conventions

Except for the explicit introductory `incomplete_rolls` demonstration, the core worked examples generate complete data. The practical CSV deliberately includes 12 missing ratings; those rows remain valid for service-time analysis. R's `NA` means missing or unknown; it is never used as a zero, false event, unsuccessful trial, or absent card. `is.na()` identifies missing entries, and `na.rm = TRUE` removes them only for the particular calculation in which it appears. This removal does not recover the unknown observation or establish that missingness is harmless.

`TRUE` and `FALSE` are logical values. Event means convert them to 1 and 0 for proportion calculations. Probability tables include zero probabilities where mathematically appropriate; zero is a valid observed count or payout. Printed scientific notation is ordinary numeric formatting, not a missing-value convention. Synthetic normal models permit every real value, and exponential waits are nonnegative; model constraints should not be inferred from a short printed sample alone.

## Reproduction and verification

Seeds are included directly in their chunks: introductory examples use 17, 23, 31, 37, 41, and 43; probability uses 1101–1105; distributions uses 2201–2205; sampling uses 3101–3109; confidence intervals uses 4101, 4102, 4104, 4105, and 4107; hypothesis tests uses 5101–5107. Some exact examples require no random seed because they enumerate outcomes or evaluate mathematical formulas.

Run each notebook's worked examples in order in a clean notebook environment. Repeating the same chunk with the same seed and R random-number settings reproduces its generated values; changing a seed, the generator settings, or the model parameters can change them. Later chunks sometimes consume values created by earlier chunks. A seed does not make a model true, make simulation a proof, or turn synthetic values into empirical evidence about an actual population.

The pinned WebR runtime and the native R verification runner execute the actual source definitions. Verification uses exact assertions where appropriate and tolerances for Monte Carlo estimates, rather than requiring simulated summaries to equal population quantities. The source remains the authoritative definition when learners change parameters or when a future course revision updates an experiment.
